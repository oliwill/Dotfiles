# Wikilink 策略

何时该建 `[[wikilink]]`，何时不该建，是播客知识库质量的核心。

## 核心原则

**Wikilink 不是装饰，是承诺**：每个 wikilink 要么指向已有页面，要么承诺未来会创建该页面。滥用 wikilink 会让知识库充斥"断链"，也会鼓励过度拆分小话题。

## 该建 wikilink 的情况

### 1. 跨期会重复出现的实体

**人物**：
- 主播、固定嘉宾 → `[[梵一如]]`、`[[沙青青]]`
- 节目中重点讨论的政治家、学者 → `[[李在明]]`、`[[高市早苗]]`
- 在多期反复登场的嘉宾

**话题/概念**：
- 跨期讨论的核心议题 → `[[中日关系]]`、`[[韩国政治]]`
- 标志性事件 → `[[甲午海战]]`、`[[2026韩国地方选举]]`
- 深度分析的概念 → `[[日本极右化]]`、`[[身份认同]]`

**机构/作品**：
- 节目本身 → `[[东亚观察局]]`、`[[番薯剥壳工作室]]`
- 反复推荐的其他播客 → `[[正文三台]]`
- 重要书籍/电影/作品

### 2. 值得展开但本期不深入的话题

如果某个话题"擦边"提及，但显然值得有自己的页面：
- `[[NYU]]` - 如果会反复讨论留学话题
- `[[东京大学]]` - 嘉宾母校，可能反复出现

### 3. 用户可能直接搜索的关键词

读者用 `llm-wiki search` 找东西时，会用什么词？这些词都该是 wikilink。

## 不该建 wikilink 的情况

### 1. 一次性提及的具体细节

- ❌ `[[10-FEET - 第ゼロ感]]` - 单期 ED 音乐
- ❌ `[[小泉进次郎]]` - 节目里被一笔带过
- ❌ `[[2026年4月23日]]` - 具体日期

### 2. 过于泛化或抽象的概念

- ❌ `[[政治]]` - 太宽泛
- ❌ `[[文化]]` - 太宽泛
- ❌ `[[东亚]]` - 用 tag 而不是 wikilink

### 3. 普通名词

- ❌ `[[书店]]`、`[[播客]]`、`[[博客]]` - 这些是普通词汇，不是知识实体

## 决策树

收到一个候选 wikilink 时，按顺序自问：

```
1. 这个实体在 wiki 里已经有页面吗？
   YES → 直接用 wikilink
   NO → 进入 2

2. 这个实体会在未来 5 期内再次被提及吗？
   YES → 建 wikilink，承诺创建页面
   NO → 进入 3

3. 这个实体是用户可能搜索的关键词吗？
   YES → 建 wikilink
   NO → 用普通文本

4. 不确定？
   → 用普通文本（保守策略，宁缺毋滥）
```

## 实战示例

### 好的例子

> [[李在明]] 与 [[共同民主党]] 内部"明清大战"加剧，[[2026韩国地方选举]] 前景未明。

- `[[李在明]]` ✓ - 跨期核心人物
- `[[共同民主党]]` ✓ - 主要政党，反复出现
- `[[2026韩国地方选举]]` ✓ - 重要事件，多期讨论

### 坏的例子（过度链接）

> [[李在明]] 在 [[首尔]] 的 [[新闻发布会]] 上说要 [[支持]] [[中小企业]]。

- `[[首尔]]` ✗ - 一次性提及的地点
- `[[新闻发布会]]` ✗ - 普通名词
- `[[支持]]` ✗ - 动词
- `[[中小企业]]` ✗ - 太宽泛

## 维护策略

定期运行：
```bash
cd ~/podcast-wiki && llm-wiki graph
```

查看 "Wanted Pages"（被引用但未创建）：
- **被 ≥3 页引用** → 必须创建页面
- **被 2 页引用** → 应该创建
- **被 1 页引用** → 评估是否值得创建，不值得就移除该 wikilink

## 反模式警告

- **链每个嘉宾**：嘉宾大部分是一次性的，只链固定主播和重要嘉宾
- **链每个时间轴里的关键词**：时间轴本身已经是检索结构
- **嵌套链接**：`[[李在明]]总统` 比 `[[李在明总统]]` 更规范
